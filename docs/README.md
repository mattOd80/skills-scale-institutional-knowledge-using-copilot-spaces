# OctoAcme Project Management Docs

Welcome to the OctoAcme Project Management documentation hub. This collection of documents provides a comprehensive guide to how OctoAcme runs projects, from initial concept through delivery and continuous improvement.

## Project Management Process Summary

OctoAcme's project management approach is built on a foundation of customer-centric values, clear accountability, and continuous improvement. The process enables teams to deliver high-quality features iteratively while maintaining transparency and psychological safety.

### Core Principles

OctoAcme's project management is guided by five foundational principles:
- **Customer-first approach**: Prioritizing customer value and usability in every decision
- **Iterative delivery**: Shipping small, testable increments to gather feedback early and often
- **Clear ownership**: Each project has a named Project Manager (PM) and Product Manager (PdM) to ensure accountability
- **Data-informed decisions**: Measuring impact and iterating based on evidence rather than assumptions
- **Psychological safety**: Encouraging open feedback, learning from failures, and continuous improvement

### Key Roles

Successful project delivery requires collaboration across multiple roles:
- **Project Manager (PM)**: Coordinates delivery activities, manages schedules, risks, and cross-team communication
- **Product Manager (PdM)**: Defines outcomes, prioritizes the backlog, and measures success against customer and business value
- **Developers**: Design, build, test, and deliver software components that meet acceptance criteria
- **QA/Testing**: Validate quality, acceptance criteria, and ensure features meet the definition of done
- **Stakeholders**: Provide business context, inputs, and approvals throughout the project lifecycle

### Project Lifecycle

The OctoAcme project management lifecycle follows five structured phases:

1. **Initiation**: Define the business need, align stakeholders, and create a lightweight project charter to authorize work
2. **Planning**: Break down work into shippable increments, identify dependencies and risks, and create an actionable backlog
3. **Execution**: Manage day-to-day delivery with regular standups, demos, and progress tracking while maintaining quality through testing and code reviews
4. **Release**: Deploy features to production following standardized release processes with appropriate smoke tests and rollback plans
5. **Retrospective and Continuous Improvement**: Capture learnings and convert them into actionable improvements for future iterations

### Communication Cadence

Regular communication ensures alignment and transparency:
- **Weekly sync** between PM and PdM to align on priorities and blockers
- **Twice-weekly standups** for the delivery team (or as agreed based on project needs)
- **Monthly stakeholder updates** to communicate progress, risks, and upcoming milestones
- **Ad-hoc escalations** as needed for urgent issues or decisions

## How to Use These Docs

### For New Team Members

Welcome to OctoAcme! Here's how to get started with these process documents:

1. **Start with the basics**: Read the [Project Management Overview](octoacme-project-management-overview.md) to understand OctoAcme's core principles, roles, and approach
2. **Understand your role**: Check the [Roles & Personas](octoacme-roles-and-personas.md) document to understand your responsibilities and how you collaborate with others
3. **Find what you need**: Use the Process Documentation Index above to navigate to specific lifecycle phases or topics relevant to your current work
4. **Refer as needed**: Bookmark this page and return to it whenever you need guidance on a specific process or phase

### Keeping Documentation Updated

These documents are living resources that should evolve with our practices:
- Submit updates via pull request when you identify gaps, outdated information, or opportunities for improvement
- Ensure consistency with existing tone and structure when making changes
- Include real examples and templates where helpful to make the documentation actionable

### Using with Copilot Spaces

These documents are designed to integrate seamlessly with GitHub Copilot Spaces:
- Add relevant process documents to the `.copilot/` directory in your project repository to provide context for Copilot
- Keep your Project Charter and related artifacts updated in your repo for Copilot to reference
- Use these docs as templates when creating project-specific guidance or customizing processes for your team
- Reference role definitions when setting up Copilot personas for different team members
